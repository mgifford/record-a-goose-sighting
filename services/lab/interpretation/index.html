Interpreting tool results

These are deliberate examples. Some trigger a tool rule without being a WCAG failure; others pass a tool but need human review. The surrounding laboratory interface is intended to be usable.

1. A best-practice finding, not a WCAG failure

Section heading

Subheading that skips a level
Tool output and review conclusion
Tool outputaxe reports heading-order as a best-practice rule.
Review conclusionNot a WCAG 2.1 AA failure, but the structure is harder to skim. Fix it.
WhyHeading order is useful for navigation, but WCAG does not require a specific level sequence.

2. A finding the tool cannot decide

Dark text on a light gradient. The measured colours pass 4.5:1, but the background is an image so automation cannot be certain.

Tool output and review conclusion
Tool outputaxe returns color-contrast as incomplete, not a violation.
Review conclusionMeasure the actual rendered colours. Do not report an incomplete check as a failure or a pass.
WhyThe tool cannot resolve a background image; a person can.

6. A tool pass that needs review: hidden instruction

Use at least three characters.

Tool output and review conclusion
Tool outputNo automated finding: the input has a label and a description.
Review conclusionManual concern. Sighted users never see the instruction; a screen reader user may only hear it.
WhyThe description is present in the accessibility tree but hidden visually.

7. A tool pass that depends on context: uninformative link text

Read more

Tool output and review conclusion
Tool outputNo link-name finding: the link has non-empty text.
Review conclusionContext-dependent, not automatically a 2.4.4 failure. In a links list, "Read more" has no determinable purpose. If the surrounding sentence names the destination, it can pass.
WhyThe rule checks that a name exists. It cannot decide whether the name identifies the destination in every context.
How to test
  1. Open the links list in a screen reader, or read the link without its surrounding sentence.
  2. Ask: can you name the destination from the link text alone?
  3. Repeat with the surrounding paragraph present. Record both observations; do not change the verdict to "failure" unless the purpose is unavailable in every realistic context.

8. A tool pass that fails review: an inaccurate image alternative

Tool output and review conclusion
Tool outputNo image-alt finding: an alternative attribute is present.
Review conclusion1.1.1 failure. The alternative does not describe the image.
WhyAutomation checks for a non-empty alternative, not whether it is equivalent to the image's purpose.
How to test
  1. Open the images list in a screen reader and listen to the alternative.
  2. Compare it with the visible image and with the image's role in the page.
  3. Record the heard alternative and why it is or is not equivalent.

9. A tool pass that needs a keyboard: visual order differs from DOM order

First item in the DOM Second item in the DOM
Tool output and review conclusion
Tool outputNo automated finding: both links have names and valid targets.
Review conclusionPotential 1.3.2 / 2.4.3 issue, context-dependent. The second item appears first visually, but Tab follows DOM order. If the sequence carries meaning, the mismatch is a failure.
WhyCSS order and flex-direction change rendering without changing DOM or focus order.
How to test
  1. Tab from the address bar through the two links and record the order.
  2. Compare it with the left-to-right visual order.
  3. At 320 px and 200% zoom, check the order again.
  4. Decide whether reading the content in the keyboard order changes its meaning.

10. A tool pass that needs a listener: an uninformative status message

No update

Tool output and review conclusion
Tool outputNo automated finding: the status region is valid and the button has a name.
Review conclusionUsability concern, not a 4.1.3 failure by itself. The message is announced, but "Updated" does not say what changed or whether the action succeeded.
WhyStatus-message rules can confirm that a live region exists; they do not judge whether the announcement is useful.
How to test
  1. With a screen reader running, activate the button.
  2. Listen to the announcement without looking at the screen.
  3. Record whether you can tell what changed and whether the action succeeded.
