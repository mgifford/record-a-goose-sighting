Record a goose sighting Laboratory

Animal reporting laboratory

These are fictional services for accessibility research and training. They are not real government services. The laboratory interface is intended to be usable; only the explicitly labelled fixture targets contain deliberately broken conditions.

Report a sighting

Three sibling services implement the same reporting journey in different rendering models. Each has a control to compare an initial and an updated accessibility state.

  • Report a hedgehog — React six-step journey, with a dynamically supplied button name.
  • Report a wombat — Vue six-step journey, with a reactive button name and live status message.
  • Report a paca — Web Components six-step journey, with an ARIA role inside an open, closed or nested shadow root.

Realistic service journey

Book a wildlife observation session — a three-step service where the defects appear across the journey rather than on a single page. The page contains no answer key.

Isolated ACT fixtures

Each fixture isolates one target for one ACT rule. Expected outcomes are unreviewed hypotheses, not verified results.

  • Valid ARIA role — rule 674b10, expected passed.
  • Invalid ARIA role — rule 674b10, expected failed.
  • Button with an accessible name — rule 97a4e1, expected passed.
  • Button without an accessible name — rule 97a4e1, expected failed.
  • Link with an accessible name — rule c487ae, expected passed.
  • Link without an accessible name — rule c487ae, expected failed.
  • Form field with an accessible name — rule e086e5, expected passed.
  • Form field without an accessible name — rule e086e5, expected failed.
  • Closed shadow root, exploratory — no ACT outcome; engine visibility is unsupported.

Inapplicable cases

These pages contain no eligible target for the named rule. “Inapplicable” is an ACT outcome, not a scanner that failed to run.

  • No buttons — rule 97a4e1 inapplicable.
  • No images — rule 23a2a8 inapplicable.

User-preference scenarios

Manual rendering comparisons. These are not ACT fixtures and do not establish conformance.

  • Reduced motion — one animation respects the preference, one ignores it.
  • Forced colours — an outline survives; a background-image focus cue does not.
  • Text spacing and reflow — increased spacing at 320 CSS pixels.

Dynamic, frame and interaction tests

Deterministic states that exercise asynchronous updates, node replacement, nested shadow roots, same-origin frames and disclosure interactions.

  • React: name supplied after mount — stable ?state=async, ready marker async-ready.
  • React: target node replaced — stable ?state=replaced, explicit replace action.
  • Vue: reactive name after mount — stable ?state=async.
  • Paca: nested open shadow roots — target inside a shadow root inside another shadow root.
  • Single frame, nested frame and two frames — same-origin targets in different browsing contexts.
  • Reveal an unnamed control — the target is absent until the disclosure opens.

Correlation experiments

Deliberate fixtures for testing target identity, duplicate detection and multiple rules on one element. These are not isolated single-target ACT cases.

  • Two distinct image failures — two failing images with the same class and a passing control; three declared targets.
  • One image, one failure — the simplest shared-target case, linked to the original confirmation page example.
  • Two rules on one target — one button, two independent ACT rule failures.
  • Repeated controls — three equivalent failures and two passing controls, each a separate target.

Subtle comparison fixtures

Each page contains two visually similar versions of one component, so that a difference in behaviour is the only signal. The pages do not state which version is defective; that answer lives in the known defect catalogue.

  • Delete action names — visible text and accessible name.
  • Selected attendees — where focus goes after removing an item.
  • Draft save and availability — silent confirmation and a busy state that never clears.
  • Observation date errors — association, summary links, focus and required state.
  • Filter disclosure — a stale expanded state.
  • Alert preference — a switch that ignores the keyboard.
  • Reference code — a hint hidden from assistive technology and a visual-only heading.
  • Observation tables — column headers that are not marked up, and a sort state that never updates.
  • Species suggestions — an active descendant that points at a filtered-out option.
  • Observation record tabs — every tab in the tab order, and no arrow-key navigation.

Interpreting results

Examples where a tool flags something that is not a WCAG failure, and examples that pass a tool but fail review.

  • Interpreting tool results — ten cases covering best practice versus failure, incomplete results, context-dependent link text, inaccurate alternatives, visual order and status messages.

Scope

Automated ACT results describe rule evaluation for declared targets. They do not establish WCAG conformance, do not rank tools, and do not cover requirements that lack an approved ACT rule. A missing finding is not a pass.
